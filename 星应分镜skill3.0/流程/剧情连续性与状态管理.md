# 剧情连续性与状态管理

本方法是跨集事实和状态的唯一规则源，01负责从原文提取，02关联真实图片，03按时点设计镜头，04继承并反查。入口见[项目关卡](项目交接与恢复.md#project-gates)，记录见[契约](项目记录契约.md)。状态表不能取代原剧本；先核依据，不能遇到本可查清的问题就问用户。

<a id="state-entry"></a>
## 必经时点

导入或采用剧本、开始一集/一场、分段成稿、续写/换会话、修改源事实或图片状态时，读取本轮相关对象和状态事件。G1核原文，G3核最终镜头/参考，保存G5。普通摄影和构图设计不得改写人物生死、伤势、身份或场景完损。

## 身份、故事时点与状态维度

- 稳定对象ID关联姓名/别名，化名和真实身份关联需证据；同名不自动合并。
- 叙述位置（第几集场镜）与故事时点分开。每个状态域用timeline；梦境/想象的临时状态不能污染现实。倒叙若属同一现实历史，用同一timeline的更早point，不用当前最新状态。
- point是有原文顺序依据的可比较数值，不冒充真实秒数。相同时点发生变化时用明确前后接点拆point；无法确定先后则保留未知并阻塞相关执行，不能按集数或数组顺序猜。
- 生死life、出场/离场presence、伤势injury、服装costume、身份identity、知情knowledge、持物holding等维度分别记录。具体字段名按项目约定稳定使用，不用一格“下线”替代所有维度。
- 缺席不等于死亡，疑似死亡不等于确认死亡，死亡角色尸体/回忆可入画；“需要活着才能完成”的行动须另核life。暂时离场不改变life。
- 长期状态有有效边界；临时动作和持物不得无依据穿越时间省略。未知不能自动等于正常或恢复。

## 状态事件

每次记录：对象、timeline、point、叙述范围、前值from、后值to、必要失效until、原文文件/版本/原句、性质和采用状态。初始基准用from空值；后续from必须与此前有效状态相符。同一对象/维度/时点不能存在互斥的采用事件。

只采用有原文或明确设定依据的事实。执行设计与候选事件另记，不混进采用事实查询。未来复活可提前登记为未来point事件，并记录出自哪一集，但在发生之前life仍是dead。疑似、未知等必须保留其不确定性，不自行合理化。

```text
state(对象, timeline, point, 采用版本)
= 该timeline下此point前已经生效且未失效/被覆盖的有效采用事件
```

每个维度单独解析，不把人物整体替换成某张图。未来知情、伤势或死亡不能提前生效。场景布局/完损、道具完损/归属也按同样机制；机位变化只改投影，不改场景事实。

## 每场/每段执行

1. 读当前采用原文，定位涉及对象、叙述范围和故事时点，查询相关状态事件。
2. 列本单元入态、实际变化、出态；源文中新变化先登记再交03，不让04临时猜。
3. 对每个关键状态接点生成observation，保存对象/timeline/point/所需维度与状态；同镜受伤前后必须分开，支持关联同源镜的不同接点。
4. 动态正文与observation逐项核对，生存行动需要的life必须显式检查；并非只要正文点了姓名就通过。
5. 将相同结果交02选图、03设计和04绑定。图像只提供参考，不反过来改变剧情事实。
6. 出态交后续单元，原稿变更触发依赖待复核。未来源稿尚未给出就标未收，不编造后续安排。

## 冲突处理

先判断是采用原文有冲突、旧版本未失效、状态登记错、分镜乱写还是提示词漏写。资料足够时自行纠正下游；原稿有两种互斥说法或缺关键决定才弹卡列源证据。只暂停受影响部分，不让无关场景被无限阻塞。

禁止通过改下一镜、换一张图、删状态栏、编治疗/假死/复活桥段掩盖矛盾。未经授权不能改原词或锁定结果。

## 跨集重点反例

- 第2集已死、第70集现实中正常行动且无复活：life冲突，按源稿查错；源稿冲突才问，不能自行补解释。
- 第70集明确复活：未来事件可被索引，但只在第70集对应point起生效。
- 第70集回忆死亡前：使用更早point正常状态，不误报复活。
- 第8集某场受伤：变化前用正常图，变化后用伤后图，整段内分职责；恢复必须有依据。
- 场景被毁后反打：保持损毁；倒叙到被毁前才恢复完好。
- 人物暂离但不死：presence更新、life不变。未知暂离结局不编成未来必回归。

自动工具只检验显式状态数据和引用，不能独自理解全剧。每集源文与事件表的完整性、状态转移的语义、梦境/倒叙分类必须由执行者核对并保存证据，不能拿脚本绿灯冒充剧情零穿帮。
