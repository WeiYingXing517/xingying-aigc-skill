# 1.0.0 验收记录

本次使用 [回归规范](回归规范.md) 中的合成样本。记录结构核查和已经出稿的试跑。用例库保留其余发布回归所需的输入与判据。

## 结构核查

- 确认只有一个入口 `screenplay-writing/SKILL.md`，入口名称与目录匹配，两个 YAML 入口字段符合约定。
- 九份参考均由入口链接，包内 Markdown 相对链接可解析，Skill 正文及参考没有旧 Agent 绝对路径、资产拆解入口或资产确认规则。
- 本机的 `quick_validate.py` 运行环境缺少 PyYAML，以上使用 PowerShell 检查当前两字段头部、引用与包结构。

## 小说改编试跑

用例取自 A1，调整为完整提供《潮痕》三章，要求只交前两集分集大纲，保留原有关系和已发生的选择，允许外化心理。由独立子代理读取新 Skill 和样本出稿。

- 初稿保留 8:40 冷开场、7:00 的片段接收、7:30 的维修记录核实、代贴封条、道歉和开门结果。集内任务融在连续叙述里，接续线索可更明确。
- 在 `episodes.md` 写明默认逐集呈现任务、起始状态、主要事件、有效进展与承接。用同样请求复跑。第 1 集从疑心和封条湿角收束，第 2 集以湿角翻出签名，核实维修原因，再以道歉、协作和开门结尾。输出只包含两集大纲。第 1 集采用倒叙开场，仍将角色怀疑留在获得维修记录之前。
- 此次核对叙事覆盖、人物知情、改编锚点和分集承接。用户请求只交大纲，来源映射在这一试跑中按原文逐项核查。

## 原创分集试跑

按 O2 的常规分集请求，子代理从《末班收发箱》的已确认故事直接出三集，每集约两分钟。第 1 集停在延后清运并找到旧房号，第 2 集停在查明新地址但签收资格仍待核，第 3 集核验交接凭证，归还未拆封的信并清空旧箱。叶琴在场且未看信。只交了分集大纲。每集有不同进展和可接续的状态，注明了估算内容负担。O2 的十秒容量冲突属于另一项测试。

## 全剧大纲与人物卡试跑

按 O1 的两个单项请求，子代理分别交全剧大纲与忠实提取的人物卡。大纲保留地址核对、签收资格核实、凭证交接、空箱清运的因果顺序及未拆封结局。人物卡收录许芃、叶琴、提供核实的值班室一方和原登记住户，材料未提供的音色和关系保持未知。叔叔只在清单中被提及，未列为实质角色。

## 局部正文与跨集复核试跑

按 S1，子代理先写《雨夜电话》第 2 集第 1 场，再应用晚进门条件。原稿听见完整电话后问蛋糕口味。修改稿只呈现「先别告诉她」及疑惑反应，罗宁挂断离开，正文没有补入场外告知。出稿采用单行场次、逐场名单、动作段和对白格式。

- 第 3 集第 1 场复核定位到冷藏蛋糕的行动缺少知情来源，并指出最小修订条件。生日、蛋糕口味及第 2 集第 2 场均留在原状态。
- 复核初稿发现可避免在动作里补写材料未交代的性别代词，并可将角色知情判断写成「听到的内容无法确定对象或得知蛋糕订单」。更新正文与审稿规则，终稿采用原有角色称谓和材料支持的认知范围。
