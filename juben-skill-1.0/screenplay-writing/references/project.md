# 项目状态与修订

在同一个项目内复用现有有效材料，按本次目标维护必要的状态。用户指定项目目录时，从其中读取当前作品资料，并按约定更新文件。未指定项目目录时在会话中维护，必要时说明如何把当前依据交给下一次会话。读取已有项目时沿用原文件结构、已有编号与可确认的版本信息，按需解释新旧字段对应，读取动作本身不触发改名、批量重写或结构升级。Skill 目录用于创作规则，项目稿件和运行时资料保存在用户指定位置。

## 当前依据

跟踪项目范围、形式、素材及可见版本、工作方式、本次目标、用户要求保留的内容与允许补充范围。标明当前草稿、有效确认稿及确认范围、未决决定、最近改动、受影响结果和实际保存位置。项目规模小时，在当前交付或会话中保持必要记录即可。

只维护一个当前有效依据。阶段确认时，新草稿与上次确认稿分别记录，新稿明确获认可后才替换确认稿。用户最新明确修改会立即约束相关内容，旧稿里与其冲突的条目不能继续无条件使用。没有明确确认的意见仍记为草稿或待确认。项目稿件修订、项目文件结构版本和 Skill 发布版本可独立追踪。

新项目按[创作需求与参考选择](brief.md)记录已确认的作品形式、题材、背景、时长、集数、目标产物、文风方向、节奏方向，以及两路参考各自的选择和核查状态。每路记录未选、待核、已选可用、资料不足或跳过，以及来源、范围和允许使用的抽象规则。改编原著单列。只更换文风时复核人物表达和对白；更换节奏对标时复核实际受影响的场次或分集。后续沿用同一项目的已确认选择。

## 事实、角色认知与引用

| 维度 | 按需记录 |
|---|---|
| 对象 | 角色 `C001`、事件 `E001`、集 `EP01`、场 `EP01-S01`，或沿用项目已有标识。发生重排时保持对象身份稳定，单独更新其显示顺序与位置，已移除的编号不再分配给其他对象。 |
| 客观事实与戏内状态 | 可确定的身份、关系、时间、地点、物件、伤势、能力和权限。记录在哪个故事时点有效、由何事件触发变化、变化前后分别是什么。 |
| 角色认知与观众所知 | 谁何时通过什么途径接触到信息、实际接收了多少、如何理解，属于知道、相信、误判、怀疑还是听闻。角色台词和传言保留说话者与依据，观众披露位置单独记录。 |
| 来源及确定程度 | 原著或用户材料的具体位置与版本、用户明确要求、由材料合理推导、授权内新增、待核冲突或未知。推导附最短依据。 |
| 采用与确认 | 分别记录创作状态（提案、已采用、已替代、已撤销）和用户确认状态（待确认或已确认）。已确认时写清依据和适用范围。 |
| 文本实现 | 记录规划位置和文本实际呈现位置。计划中的事件不改变当前戏内状态。 |

需要跨集续写、核对事实或做影响较大的修订时，使用上述记录做事实台账。用户要求单独交付时，提供当前版本及覆盖范围、事实和认知条目、有效时点、开放项、冲突与影响。只做局部查询时给对应事实与实际可核的来源。

## 确认与续写

默认按需交付。用户要求逐阶段确认时，采用约定的阶段和当前确认点。未约定顺序时，从当前任务需要的阶段开始，可依次采用创意理解、梗概或全剧大纲、人物卡、分集大纲、场次蓝图、逐集正文。单部作品按场次组织，已有有效材料可直接承接，确认只覆盖当前实际展示的范围。

用户明确说“确认，继续”或明确认可并要求下一阶段，锁定刚展示的范围并继续。只认可部分时记录范围，修改当前成果或要求继续完善时留在当前阶段，询问理由或无回复时保持等待。“修改后直接下一步”按明确授权执行。内部检查通过与用户确认分别记录。

续写前先核对当前有效版本、上一集结束状态、待兑现内容和本集入口。材料不足时限定已核查范围。未找到历史文件或确认依据时，保留未知，并根据可读材料完成能独立处理的部分。

## 局部修改与恢复

1. 识别用户改动的事实、人物、事件、集或场，以及它们引用的上游和被引用的下游。必要时通过文本和情节关系补找没有编号的依赖。改动触发、认知或行为后检查后续反应、结果与相邻集承接。
2. 修订当前授权范围；已有无关内容继续有效。需要一并同步且已在本次范围内的产物更新到一致版本，其余实际受影响的条目标为待复核。依赖的旧版本无法核实时注明范围，完成声明以实际读取和校验为准。
3. 跨文件保存时，先核对读到的版本，写入后检查正文、当前依据和引用一致。遇到中断或发现文件有新修改，先读最新状态并核对已完成部分，再续写。用户要求回退时，以可用历史恢复为新的当前修订，记录原因并重新确认受影响下游的有效性。
