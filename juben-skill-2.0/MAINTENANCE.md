# 维护剧本创作 Skill

安装时使用 [`screenplay-writing/`](screenplay-writing/)。本文件、[变更日志](CHANGELOG.md) 和 [回归规范](tests/回归规范.md) 随维护包保存。项目原文、成稿、确认记录和故事事实放在各自项目目录。用合成样本记录公共回归，真实素材按项目约定处理。

## 从反馈到修订

1. **记录实际问题。** 写明触发请求、Skill 版本、运行模型、素材版本、具体集场或段落、期望结果和实际偏差。选一份可重复使用的输入，把和问题无关的细节去掉。
2. **找到规则归属。** 项目偏好写进项目记录。通用入口和交付范围由 `SKILL.md` 维护。来源追溯、产物结构、项目状态和审稿分别修改对应参考。优先修正或合并已有规则。新增条款时写清适用条件及一个反例，引用同一条规则即可覆盖多处使用时，只维护一个正文。
3. **缩小改动范围。** 若问题来自素材缺失、用户约束冲突或一次执行偏差，先在该任务内处理。研究和反馈可形成候选写法，依据、适用条件及对照结果支持后再合并。把失效或被替代的条款从运行说明移除，历史留在版本记录中。
4. **复跑后发布。** 用原始失败例、一个规则不应触发的反例，以及相邻产物做回归。路由、项目结构或共用规则改动时，再跑固定核心用例。评估规则变化时固定模型与素材。模型变化单独对照。每次发布记录具体执行结果、覆盖范围和待核问题。

| 改动位置 | 优先复跑 |
|---|---|
| `SKILL.md` | 原创、小说改编、单项交付、已有大纲直接分集、逐阶段确认 |
| `adaptation.md` | 全文、缺章、调序与内心戏外化 |
| `outline.md`、`characters.md`、`episodes.md` | 对应产物与相邻产物、已确认条件复用、纯提取与授权创作、容量和末集收束 |
| `script.md`、`review.md` | 知情、原话接收与承诺强度、大纲视角泄漏、普通对白、修订影响、正文格式和逐场名单 |
| `style.md`、`style-samples.md`、`curves.md` | 人物情绪与起伏文风回归中的触发例、普通直答与外放反例、同条件试稿、未确认状态、图稿一致性和端到端任务；跨模型效果另行实跑 |
| `expectation.md` | 首要期待、阶段回报、爽点实际后果、非爽剧反例、完整三集正文及局部修改的端到端用例 |
| `ideation.md`、`genre.md` | 机制不同的候选、已定方向不重开、类型差异、普通合作反例、动作与规则条件 |
| `risk.md` | 具体风险末尾告知、涉警与亲密互动不误报、证据分类、不采纳与已消除状态、边界不由免责声明放行 |
| `project.md` | 旧项目读取、迁移重试、续写、回退、未知与未确认的状态 |
| `production.md`、`research.md` | 对应专项能力和一个普通创作请求 |

例如，某部短剧要求每集前三秒有冲突，记入该项目。若通用回归发现独幕短片也被强塞冲突开场，就修正 `episodes.md` 里的适用条件，同时用短剧和短片复跑。

## 版本和兼容

- **Skill 发布版本**标识当前运行规则与参考。规则有变更时在维护包记录版本、改动、影响和实际回归结果。有 Git 时用标签或提交标识同一快照。
- **项目修订**标识一次内容变化。**项目结构版本**标识存储字段和含义，兼容范围以实际验证过的版本为准。会话内的轻任务可以不落盘。已落盘项目按对应参考加载。
- 读取旧项目时，按已有字段解释记录。没有确切依据的值保留未知。需要升级结构时，先用项目副本验证。保留稳定编号、来源、确认状态、草稿和未识别字段，检查前后差异及集场引用，再按实际迁移方式测试中断重试和重复执行。旧结构首次导入时核对当前有效稿的依据。
- 回退 Skill 时使用前一可用包，保留项目最新内容。若前一版本无法读取当前结构，可用兼容读取或在副本转换，必要时继续使用能读取该项目的版本。回退项目内容时生成新修订，核对上游引用、受影响集场和未决状态。

## 发布检查

从独立目录复制整个 Skill，核对仅有一个 `SKILL.md`，内部引用有效且可按需读取。用正常入口跑回归，在看不到旧 Agent 路径的会话验证主要任务。切换时保留上一版本和项目备份，确保发现路径只有当前入口。按 [回归规范](tests/回归规范.md) 保存可查证结果，再更新 [变更日志](CHANGELOG.md)。
