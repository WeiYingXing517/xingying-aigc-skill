# 文风底线、项目档案与校准

用于正文创作、对白和文风回修。不用于纯提取、只审稿或格式整理的自动重写。规则和样本能约束可观察的写法，不能移植某个模型的全部能力，也不保证跨模型质量；实际效果须按同输入对照验证。候选样本不是用户认可稿。

## 最低写作要求

1. **动作可拍。** 重要动作交代必要对象、先后和结果；空间影响理解时补定位。抽象感叹、心理诊断和主题判断不能代替应呈现的行为。无关动作不为细腻而添加。
2. **对白有眼前用途。** 人物在处理当前的人与事；伏笔和主题不能成为唯一开口理由。普通直答、闲谈和必要说明可以成立。
3. **交流有接收。** 关键回应承接话语、动作或有效前情；反馈改变下一步或维持有依据的选择。沉默也要有现场作用。
4. **情绪有来源与余波。** 按实际知情、人物理解和关系写变化，不堆情绪标签，不让重大伤害被一句话抹平。明确不等于全部说破。
5. **声音来自人物。** 从关注点、依据、关系策略、直接程度和句子节奏形成差异；不靠口头禅、粗口、随机病句或一律短句。
6. **修辞服从场面。** 文雅、演说、直白和碎句都可在有据情境成立；不按禁词或固定句长判优劣，不把所有作品改成冷淡口语。

出现冲突时，用户本次明确要求和既定事实／人物边界优先，其次是仍适用的项目文风档案，再次是抽象偏好及候选样本；底线中的因果、知情和可理解性不能为模仿牺牲。只改文风不擅添事件、道具、旧话、身世或关系。

## 项目文风档案

仅在项目需要时维护短档案，复用[项目状态](project.md)，不另造强制目录。记录动作细腻度、对白口语／类型化／文学性、情绪外放程度、直说与潜台词、交流节奏、修辞适用边界，以及用户认可和不认可的具体片段及原因。不同人物可以不同，场景功能也可改变表现。偏好未定时采用「清楚、具体、有接话、情绪可追溯」作为工作默认，不标为用户已确认。

用户想固定喜欢的写法时，先用同人物、同事实、同场景任务提供少量不同表达试稿；只有用户明确认可的范围进入已确认档案。喜欢方案说明不等于认可剧本文风。用户要直接成稿时不强制试稿审批；沿用工作默认或已知偏好，交付可继续校准。已确认样本优先于候选样本，但仍只学习手法，不照搬桥段和原句。

## 写作与局部回修

1. 写正文前读取本页最低要求及项目适用档案；关键场需要时再读[原创校准样本](style-samples.md)中一到两个同任务片段，不加载全部例子强套。外部作品按[研究](research.md)核查，样本中的具体人物、物件和台词不迁入项目。
2. 先确定知情、现场用途、行动和情绪链，再写语言。借鉴的是如何让动作触发接话、让关系改变表达，不是复制句型、停顿位置和克制程度。
3. 第二遍仅定位实际缺陷：哪句无开口理由，哪次反应无刺激，哪段解释代替动作，哪个关键回合人物可任意互换，哪次修辞妨碍理解。用具体位置和依据判断，不以自评分数作为通过条件。
4. 修最早根因和实际依赖，回读前后文；没有缺陷不为显示润色重写。新稿更机智却不符合角色，不算改善。用户只要正文时，检查留在内部，不额外交付整份审稿表。

回修采用有限轮次：先做一次整合检查，再修实际缺陷并回读；只有仍存在明确阻碍理解、知情或必保条件的问题时继续针对性处理。没有新证据不反复全文润色。缺素材、授权或能力无法消除的问题，明确具体位置与待补条件，不以反复自评或擅改设定掩盖。保底要求是可检查的约束，不是跨模型效果承诺。

长篇分批时保留最短交接摘要：有效稿和检查范围、人物知情与未消化情绪、当前目标及待回收事项、适用文风条目与认可片段位置。缺文件或缺前情说明实际覆盖，不能声称读取过或按样本验收。

## 跨模型与迁移验收

将规则、用户已确认档案、必要样本与本次材料一起交给实际执行模型；不依赖模型名、旧会话记忆或只写一句「按之前的风格」。如果环境不能按引用读文件，提供相关正文而非只给路径；未读内容不算已加载。默认样本不得自动变成用户长期风格。

用同素材、同任务、同约束比较旧规则与新规则，另用未展示的场景检查迁移，保留失败稿。对照顺序尽量匿名，分别记录事实和知情、接话、人物差异、情绪连续性、动作可演与项目风格匹配。缺实际独立运行时只记规则审查；同一会话自检不冒充跨模型测试，文本改善不等于受众效果。
