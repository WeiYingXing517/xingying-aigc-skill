# 剧本创作 Skill 回归规范

这些用例提供输入与判据。以实际生成的文件、回复和行为记录验收结果。

## 运行方法

1. 将整个 `screenplay-writing/` 放入临时验证环境。确认只有一个 `SKILL.md`，YAML 的 `name` 与目录匹配，`description` 可用于发现。检查 `SKILL.md` 到各参考的相对链接，确认在旧 Agent 不可用的环境也能通过正常入口运行。可用 `quick_validate.py` 验证入口元数据。
2. 对照旧版时，固定模型、任务、输入和用户约束，在干净会话分别运行两版。旧目录依赖需要修正时，只修改临时基准副本的路径并记下差异。若旧版无法运行，记录缺失的基准，用可查旧样稿与现有规则作对照。新增小说改编直接按原文验收。
3. 仅提供本次要求及样本指定范围。由审阅人保留判据，优先使用独立会话执行。首次发布或改动共用规则时，对关键案例重复试跑，保留失败输出。改动单项时至少复跑触发例、反例及直接受影响的相邻产物。
4. 检查硬要求后，以匿名顺序审阅共同任务的两版成稿。具体位置可指出集、场、对白或原文章节。形式结构可用脚本检查，叙事因果、动机、对白自然度和改编取舍由成稿审读判断。

## 核心用例

| 编号与输入 | 可观察的通过条件 |
|---|---|
| O1。用[原创素材](样本/末班收发箱.md)。分别请求「只给一句话故事梗概」「只写全剧大纲」「按材料只交主要人物卡」。 | 每次仅交请求范围。完整大纲交代关键选择、结果与终局，人物卡有独立的行动依据。姓名、关系、核心结局和明确限制得到复用。 |
| O2。用同一素材的已确认故事走向，要求「做 3 集，每集约 2 分钟，只交分集大纲」。另试「保留三段行动和半小时等待的连续实时呈现，禁止跳时或压缩，压成一集 10 秒」。 | 第一项有三集，每集任务、起止状态、有效推进和末集收束明确。第二项说明容量冲突及可选取舍。估算有依据。 |
| O3。用同一素材，分别请求「完整写 3 集短剧，每集约 2 分钟」和「完整写一部 8 分钟短片，按场次组织」。 | 两个成稿都覆盖约定范围，事件与结局成立。短片按全片节奏组织。检查场次、可表演动作、人物行和自然对白。 |
| A1。给[小说全文](样本/潮痕.md)，要求「改编为三集短剧，先给分集大纲及关键原文对应，保留许舟只是代贴封条、门缝封条的线索和末尾开门结果」。 | 开场倒叙与实际时序可分辨。许舟的说法、来电内容和已证实事实各有依据。关键改编取舍能从章节回查到集，主要结果保持，第三集有收束。再写关键场时，内心活动落实为可观察的选择、动作或对白。 |
| A2。只给[小说](样本/潮痕.md)前两章。先请求「只从已给章节提取人物卡和声音，禁止补写」，另开会话请求「保留第 1 章的开门结果，提出一种方式补写缺失经过，并标出新增」。 | 第一项明确材料范围，未出现的音色和封门原因保留待补。第二项保留已知结果，标明新增和建议状态，原文与提议可区分。 |
| S1。用[场景与续作素材](样本/雨夜电话.md)第一部分前三条写 `EP02-S01`。第二轮补给第四条修改条件，并要求复核第 3 集。 | 最初人物行为符合完整听到的内容。局部修改后，第 2 集的判断、情绪和对白与片段信息吻合，修订或标注第 3 集依赖知情的场次。保留无关场次，复核不凭空补告知或新危机。 |
| S2。给[场景与续作素材](样本/雨夜电话.md)第二部分，要求「只精修动作、对白和逐场出场名单」。 | 出场按实际呈现整理，无台词者、电话声、回忆和照片得到恰当标记，仅提及者排除。递毛巾可保留为普通关心。按要求交正文，剧情所需的物件仍能在场景里核对。 |
| P1。用[原创素材](样本/末班收发箱.md)要求「逐步确认，先只交梗概」。交付后回「解释为什么」，随后回「继续完善」，最后明确「确认，做人物卡」。 | 解释与完善阶段维持在梗概。最后一次明确确认才进入人物卡。将确认和当前稿按约定写入临时项目目录，在新会话请求续作，核对恢复的任务、确认范围、有效稿与待复核项。 |
| P2。把[场景与续作素材](样本/雨夜电话.md)第三部分保存为临时旧项目记录，先要求只读查询，再在副本请求接续和按需导入。 | 只读时文件内容相同。副本中的稳定编号、用户确认、来源、草稿和未识别字段均可核对。目标修订只改所需范围。有结构转换时验证重复执行和中断重试。后续发布如支持前一结构版本，补测新版续作和回退读取。 |
| X1。用[原创素材](样本/末班收发箱.md)分别请求「只做因果审稿」「只做连续性审稿」「仓库场景拍不了，只用走廊和两位演员做制作适配」。 | 审稿指出实际位置与最小建议。制作替代保留原叙事作用。常规交付保留正文场次和人物，不产生分集资产清单或资产确认。 |
| X2。用[小说](样本/潮痕.md)与[专项对照样本](样本/专项对照.md)第一部分进行原创对照。另用第二部分比较两份合成平台资料，要求仅依据给定材料核查适用范围。 | 对照基于实际节选，能区分通用手法和相似的具体表达。平台判断明确材料出处、日期、适用范围和未知项。 |
| X3。用[专项对照样本](样本/专项对照.md)第三部分验证「少用重复解释对白」。 | 指出两个版本的可见依据、信息差异和潜在损失，提出限定适用条件。单个文本样本的结果仅作为候选方法证据。 |

## 硬要求与成稿评审

硬要求逐项记录通过、失败或未覆盖。至少检查交付范围、用户必保条件、来源覆盖、关键知情与因果、跨集连续性、正文格式、确认和局部修订边界、移除分集资产交付。任一失败时定位根因，修复后重跑相关用例。未覆盖项写明需要的输入或能力。

对适用维度记录 `0`、`1` 或 `2`。`0` 为关键缺口，`1` 为局部可修，`2` 为达到当前交付要求。附一处以上可复核证据。共同任务中的关键维度应达到基准。新增改编任务依据原文和交付约定判断。

- **故事因果**。关键行动有触发、必要条件和可理解后果，高潮与结局有铺垫。
- **人物**。选择符合动机、关系和已有认知。重要角色的用语或行为有辨识度。
- **分集**。每集发生可说明的进展，下一集能承接前一集的有效状态，末集有当前故事的收束。
- **正文**。动作可表演，信息在角色能感知的地方出现，关键对白有承接。根据实际文本判断，不用反转数量或情绪标注数量代替。
- **改编**。必保锚点可查，核心动机成立，调整后的时序和信息可追溯。内容估时和观众表现分别以实际证据判断。

记录每次使用的 Skill 版本、执行环境、日期、用例、素材范围、输出位置、实际证据、结论和修订后复跑结果。按用例分别标通过、失败、未运行或受阻；额外合成片段不替代正式编号用例，历史版本结果不自动沿用为新版通过。执行环境有基准缺口或版本限制时一并记下。
