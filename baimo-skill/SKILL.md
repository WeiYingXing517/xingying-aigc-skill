# 白模搭建与分镜白模导演台

默认Three.js白灰简模。用户指定其他工具时按要求适配，能力不具备则说明，不默换工具。交付真实可打开工程和实际制作结果，不以代码片段或方案代替白模图片。用户只要方案时不创建文件。

## 任务与边界

- 场景模式：根据场景图搭建筑、家具、主要物件，默认不加人物、不安排站位、不设计分镜。观察相机仅用于查看和参考视角匹配。
- 分镜模式：复用采用的场景版本，按明确分镜落实人物站位、朝向、起始姿态、持物和拍摄机位，默认每源镜号一张起始构图图。不是动作终态、接触表或运镜动画；其他关键帧仅按要求扩展。
- 局部修改：沿用工程和用户手动保存结果，仅改授权对象/镜头。用户只移动观察相机不意味着修改分镜。

独立接受场景图、已有分镜或工程，不依赖分镜Agent及其他Skill。沿用输入已确认的固定结构、位置路线、姿态接触、机位轴线和构图，落实几何与相机参数，不另切镜、不暗改剧情或锁定设计。普通白模实现细节在授权内完成；缺少会改变原设计的关键条件时向用户明确具体问题，其余部分继续。已有分镜足够时直接制作，不要求额外专业卡。

## 最小执行路线

1. 提取终点、范围、图像/分镜版本、锁定项和已有工程。读取当前项目里相关反馈与本skill[经验入口](experience/wen-ti-yu-gai-jin.md)，只取相关项。
2. 检查运行依赖，按[使用说明](references/dao-yan-tai-cao-zuo.md)复制模板到当前项目。通用代码在skill，图片、用户剧本、项目工程、输出和截图在项目工作区。不得覆盖已有工程或为缺依赖自动安装、上传、付费、发布。
3. 场景任务读[场景图重建](references/chang-jing-tu-zhuan-bai-mo.md)；分镜任务读[起始白模](references/fen-jing-qi-shi-bai-mo.md)。图像须实际看过才能称观察；单图隐藏空间和尺寸只作明确假设，不称精确重建。
4. 使用[数据约定](references/gong-cheng-shu-ju.md)建立或修改project.json，载入导演台。提供相机和对象操作能力，保存全部相关镜头状态，不让用户手动操作成为必经步骤；用户让我制作时由我完成。
5. 实际打开查看、导出并检查PNG；按[验证规则](references/jian-cha-yu-die-dai.md)修自身错误，仅复查受影响关系。未实际渲染不称图片完成，静态图通过不等于动画或视频验证。
6. 交付可运行入口、project.json、请求的PNG及必要假设/未覆盖项；专业中间卡默认不展示。没解决的关键项标草稿，其余继续。

## 导演台实现要求

模板在[templates/threejs-director](templates/threejs-director/README.md)，固定Three.js r180源码随包，无外部CDN。双视图分开观察相机与拍摄相机；保存镜头包含完整对象起态与相机、源镜号/版本。工程用显式文件保存/载入，自动草稿只是辅助，不以聊天或浏览器缓存代替持久文件。

场景模式禁止添加人物和分镜，模式切换不自动造人物或镜头。编辑对象可移动、旋转、缩放，简化人形可选基础姿态和四肢角度；不是精细骨骼动画。拍摄相机可数值调整或取当前观察视角。图片输出隐藏网格、标签、相机辅助和选中控件，不隐藏本身应出镜的对象。

## 迭代与权限

先修本次，再记录真实问题。分清工程误填、程序缺陷、skill方法缺口、个人偏好和上游矛盾。经验按条件/证据/原因/修正/适用范围/验证层级保存；同类更新，失效停用。项目专属内容留项目，通用摘要才入本库。没有实际错误不造历史。

涉及核心职责或通用规则修改，提出具体改动并按用户授权执行；不自动修改其他skill、不后台学习。采用相关[回归案例](evals/cases.json)检查是否复发并核对正常场景，保旧版和变更依据。只运行与修改相关的验证，不每次全量重跑；文本、数据、画面、操作和用户审美确认分别记录。
