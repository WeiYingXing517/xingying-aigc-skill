# 项目记录契约

本契约配合[项目管理](项目交接与恢复.md)、[状态方法](剧情连续性与状态管理.md)及 `工具/项目管理.cjs` 使用。项目唯一权威索引为 `00-项目管理/项目.json`，入口和总览为派生视图，不手工维护两套事实。完整正文在独立文件，原文才是剧情证据。

## 初始化、查询与原子写入命令

```text
# 初始化与只读查询
node "<Skill目录>/工具/项目管理.cjs" init "<项目目录>" "<项目ID>"
node "<Skill目录>/工具/项目管理.cjs" check|status|render "<项目目录>"
node "<Skill目录>/工具/项目管理.cjs" state "<项目目录>" "<对象ID>" "<timeline>" "<point>"
node "<Skill目录>/工具/项目管理.cjs" affected "<项目目录>" "<变更ID>"

# 原子写入命令（由 工具/项目写入.cjs 执行，支持 --expected-revision 与 --json - / --json-file）
node "<Skill目录>/工具/项目管理.cjs" add-doc "<项目目录>" --id D1 --path 01-剧本/原始输入/ep1.txt --kind script --version v1 [--depends D0]
node "<Skill目录>/工具/项目管理.cjs" adopt "<项目目录>" --scope EP001/SC001 --stage 01 --doc D1 --source "采用依据"
node "<Skill目录>/工具/项目管理.cjs" add-object "<项目目录>" --id P1 --name 阿宁 --type character [--aliases 宁儿]
node "<Skill目录>/工具/项目管理.cjs" add-event "<项目目录>" --json -
node "<Skill目录>/工具/项目管理.cjs" register-image "<项目目录>" --json -
node "<Skill目录>/工具/项目管理.cjs" set-setting "<项目目录>" --id S1 --key segmentSeconds --value 15 --status confirmed --scopes EP001 --source "确认来源"
node "<Skill目录>/工具/项目管理.cjs" set-coverage "<项目目录>" --received EP001,EP002 --unknown true
node "<Skill目录>/工具/项目管理.cjs" upsert-unit "<项目目录>" [--set-current] --json -
node "<Skill目录>/工具/项目管理.cjs" record-check "<项目目录>" --unit U1 --gate G0|G1|G2|G3|G4|G5 --result 通过 --evidence "核查依据" [--events E1]
node "<Skill目录>/工具/项目管理.cjs" mark-unit "<项目目录>" --unit U1 [--work 已交付] [--review 通过] [--adoption 已采用] [--commit-batch B1]
node "<Skill目录>/工具/项目管理.cjs" begin-batch|commit-batch "<项目目录>" --id B1 --summary "说明"
node "<Skill目录>/工具/项目管理.cjs" add-issue|resolve-issue "<项目目录>" --id X1 ...
node "<Skill目录>/工具/项目管理.cjs" trash "<项目目录>" --id T1 --path 03-资产/旧图.png --category 图片 --reason "原因" --restore "恢复说明"
```

`affected` 只读列出文档、采用路由、对象、图片和工作单元的影响范围：若传入不存在的 ID 会返回 `found: false` 并以非零退出；若变更为状态事件，同时给出按故事时点收窄的 `preciseUnitIds`（同 timeline 且 `point >= event.point` 及下游闭包）和保守范围 `unitIds`。所有写入命令先在内存中预校验，通过后以临时文件原子替换落盘、递增 `revision` 并自动 `render` 刷新总览；失败不改权威记录。`trash` 会先检查全项目采用路由与活跃单元绑定，仍有活跃引用时拒绝移动。

## 顶层字段

- schemaVersion固定3，projectId非空，revision非负整数。
- currentUnit当前工作单元ID或空字符串；coverage记录已收剧本集数/范围和未知后续，不由工具推断完整性。
- documents、adoptions、objects、events、images、settings、units、checks、issues、batches、trash均为数组。引用用ID，不以显示名或文件修改时间替代。
- 下述required数组即使空也显式保存。未知/不适用按字段约定标记；不可用空数组逃避必要语义检查。

## 文档、采用和身份

- documents：`{id,path,version,sha256,kind,dependsOn:[{id,sha256}]}`。path为项目内相对文件路径，不能越界或经符号链接跳出；sha256为实际文件摘要。kind例如script、shots、prompt、record、media。修改内容产生新版本/重新核依赖，不靠更新哈希绕过复核。
- adoptions：`{scope,stage,documentId,source}`，同scope/stage只允许一个采用稿。scope例如EP008/SC003，source为用户采用依据。文件可并存，只有路由决定当前采用。
- objects：`{id,name,type,aliases:[]}`，type为character/scene/prop/reference，ID项目内稳定。
- evidence：`{documentId,quote}`，quote是源文件中实际可定位的必要原句（校验时统一去 BOM 及 `\r\n`→`\n` 归一化，避免 Windows 换行符误报）。它只能证明片段存在，不能证明语义理解正确。

## 状态事件events

```json
{"id":"E08-INJ","objectId":"P001","timeline":"main","point":803.5,"until":null,"scope":"EP008/SC003","status":"adopted","from":{"injury":"normal"},"to":{"injury":"injured"},"evidence":{"documentId":"SCRIPT08","quote":"阿宁左臂被划伤。"}}
```

point为已核实的顺序坐标，非真实秒数；until不为空时必须大于point，为失效的开区间边界（过期后不自动回弹旧值；若在 `point === until` 处登记无缝恢复事件，其 `from` 可承接刚到期的紧邻前值或留空）。status为adopted/candidate/superseded，仅adopted参与有效状态解析。from和to为非空维度映射，初始基准from可为空；每个to维度必须为非空字符串。事件只在timeline内生效。同对象同point同维度冲突、from与此前状态矛盾会报错。初始基准from空不代表可以反复清空历史，后续变化须写前值。

同一时点多维度可分别变更；暂离只改presence，不改life。未来复活是未来point的life变化，不修改早期事件。没有提供的后续不用造事件。原文中执行设计/未知不登记成adopted事实。

## 图片images

`{id,objectId,name,path,sha256,sourceRef,version,status,viewed,state:{},roles:[],source}`。available图的sha256必须与实际文件一致，原地换图也会使登记校验失败，不能只靠文件名维持旧绑定。

- status为available/session-only/retired；available必须有可读图片相对路径。sourceRef保存实际上传/生成来源定位；source保存用户指认依据；viewed如实布尔记录。视觉类职责绑定要求 `viewed: true`；无读图能力时必须显式填写 `unviewedAck` 说明风险与指认来源，否则报 `UNVIEWED_IMAGE`。
- state记录图片已知外观/布局/伤势等视觉维度，例如`{"injury":"injured"}`；不能因是人物图就虚构life/presence/knowledge值。视觉类职责绑定时会按 `observation.requires` 中的视觉维度（或 `need.requiredStateKeys`）反向核对 `image.state` 是否齐全且一致，漏写维度或传空 `{}` 将报 `IMAGE_STATE_MISSING`，不能绕过校验；音色等非视觉职责（`timbre/audio/voice/sfx/music`）不受视觉状态限制。
- roles为实际允许职责，例如appearance/layout/voice（兼容timbre）/style；角色声纹锁图可直接关联该角色 `objectId`（或挂在 `reference` 对象上填 `forObjectId` 指向该角色ID）；没有职责的图不能直接用于绑定。
- 仅会话图path为空、status=session-only，不能作为跨会话可用图通过绑定检查。缺导出能力先登记事实，再请求可保存文件，不伪造路径。
- retired或垃圾箱图不参与现行绑定。需要历史查阅可保留登记，不能替代采用图。

## 设置settings

`{id,key,value,status,source,scopes:[]}`，status为recommended/confirmed/authorized。`scopes` 支持全项目 `*`、精确范围（`EP001/SC001`）及层级前缀（`EP001` 自动覆盖 `EP001/SC001` 等子范围，不会误匹配 `EP0010`）。同一 `(key, scope)` 下存在互斥确认值会报 `SETTING_CONFLICT`。value不能空，confirmed/authorized必须有真实来源source，不能伪造确认记录。

## 工作单元units

```json
{
  "id":"EP008-SC003-V02","scope":"EP008/SC003","parentId":"","stage":"04V",
  "workStatus":"进行中","adoptionStatus":"草稿","reviewStatus":"未检查",
  "next":"核对伤后图","blocker":"",
  "documentIds":["PROMPT08V02"],"sourceDocumentIds":["SCRIPT08"],
  "dependsOnUnits":[],"requiredSettings":["SEGMENT15"],"requiredGates":["G0","G1","G2","G3","G4","G5"],
  "observations":[{"id":"O1","shotId":"S008","objectId":"P001","timeline":"main","point":803.6,"requires":{"life":"alive","injury":"injured"}}],
  "referenceNeeds":[{"id":"N1","observationId":"O1","role":"appearance","mode":"image"}],
  "bindings":[{"needId":"N1","imageId":"IMG-INJ","label":"阿宁-左臂受伤外观图"}]
}
```

sourceDocumentIds为本单元事实原文；documentIds为产物；两者必填。dependsOnUnits记录直接依赖（含上游步骤/受影响前段），不能只填父级层次代替依赖。parentId可空，但有值须存在，不能成环。

observations逐接点记录实际正文采用状态，requires不能为空；character的动作观察点应含所需life检查，不能靠脚本猜该动作是否需活着。源镜shotId必须能定位。point必须按原文解释，不按输出段号猜。

referenceNeeds从逐镜实际用途提取，不是全资产清单。mode=image/text：text必须有明确用户许可authorization（如用户明确不做资产图，改用固定文字外观锁）；image必须有一个匹配绑定，多图分别建职责需求。bindings每项引用需求/登记图/块内清晰图片名称label；同图可复用于多个需求，同名称不能指不同图、同图不设多个名称。工具默认按图片state和观察点有效状态严格双向核对，禁止私自拿错状态图凑数；**仅当用户弹卡明确授权“懒得重做新状态图，沿用正常图参考基础外观+正文文字补状态”时**，允许在对应 binding 写入 `overrideDims: ["injury"]`（按实际放宽维度填）与非空 `overrideAuth`（用户确认依据），工具仅对该授权维度放行，无 `overrideAuth` 将报 `OVERRIDE_AUTH`，其他未授权维度仍严格校验。

## 检查checks与分级指纹失效

`{id,unitId,gate,result,inputs:[{id,sha256}],contextHash,basisEventIds:[],basisEventHash?,basisImageIds:[],evidence}`。gate为G0—G5；result为通过/失败/不适用。推荐使用 `record-check` 子命令自动收集对应阶段的输入闭包与指纹，避免手拼出错。

工具导出分级指纹 `gateFingerprint(project, unit, gate)`（底层采用键序无关的 Canonical JSON 哈希）：
- **开工原料指纹 `preFingerprint`（G0/G1/G2）**：覆盖本单元范围、阶段、源文档闭包、上游阶段采用路由、适用设置及直接上游单元的内容指纹；G1 另记录 `basisEventHash` 核对所读状态事件。写产出、更新状态或标已采用不冲掉 G0–G2。
- **素材绑定指纹 `bindingFingerprint`（G3）**：在前置基础上覆盖 `observations`、`referenceNeeds`、`bindings`、绑定图片哈希/状态/职责，以及按 `(objectId, timeline, point <= maxPoint)` 严格因果过滤的相关已采用事件。
- **成稿交付指纹 `deliveryFingerprint`（G4/G5，兼容导出为 `fingerprint`）**：在绑定基础上覆盖 `documentIds` 产物闭包与关联开放问题。

分级指纹明确**排除** `workStatus / reviewStatus / adoptionStatus / next / blocker`、其他集数的采用路由以及未来/其他时间线的状态事件，确保长剧推进第2集或采纳第1集时不引发前集雪崩失效；而修改源稿、早期状态、绑定图片或设置会精准触发受影响关卡失效。

工作单元标已交付或检查通过时，requiredGates必须有当前有效证据；下游有依赖单元未通过/待复核也报错。候选事实变化不能冒充自动采用。

issues：`{id,scope,unitIds:[],status,summary}`，status=open/resolved；开放问题关联单元须保持阻塞/待复核，不能同时交付通过。

batches：`{id,status,summary}`，status=pending/committed；任何pending在恢复时需对账，不能宣称全部已保存。

trash：`{id,originalPath,path,reason,replacement,restore}`，原路径和新路径均项目内相对路径，新路径须在99-垃圾箱。保留引用历史，不自动移动或删除文件。

## 指纹和能力边界

工具导出`fingerprint(project, unit)`供执行脚本在完成实际检查时记录contextHash；不是调用该函数就代表关卡通过。它包含源文依赖、相关对象状态/图片、适用设置、采用路由及直接上游数据。只要相关事实变化就需要重新检查，不能机械刷新指纹保绿。

项目记录可读但未通过校验时，先报告实际问题，不把派生总览当正确事实。原文遗漏事件、工具未被实际调用、图像视觉内容或正文表述错误不能由结构检查独立保证，仍须按方法做语义及生成验收。
