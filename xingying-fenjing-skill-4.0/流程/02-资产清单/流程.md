# 02 资产清单

先按[项目关卡](../项目交接与恢复.md#project-gates)恢复采用剧本、资产与版本，按[剧情连续性](../剧情连续性与状态管理.md#state-entry)取得本轮对象在对应故事时点的有效状态。所需资产、真实图片登记、采用决定、每块实际绑定为四种不同记录，不能互相替代。每批处理后执行G5保存读回与进度更新。

资产清单被采用后，按[项目交接与恢复](../项目交接与恢复.md)登记资产表版本、适用范围和需恢复的资产例外。

**输入**　用户给出的场戏或采用版场戏卡、事件链、现有设定与素材。沿用明确的资产和命名，补齐当前任务所需的对象与状态。

## 列本轮资产

1. 沿事件找角色、场景、关键道具、声音和实际需要的参考，按[资产识别与状态记录](#part-11)登记及去重。
2. 按[版本与参考职责](#part-10)核素材适用范围、采用版及缺项。缺素材时列对象、用途和待补状态，继续整理其余资产。若用户明确**不做资产图（纯文生视频）**，仍保留极简的**固定文字视觉锚点表**（每个主要角色 1 句不变硬特征：年龄/发型/五官辨识点/服装主色与当前状态；场景 1 句核心地标与光色），供 04 写入每块【角色与场景固定外观（纯文字锁）】防跨段漂移。
3. 按[资产清单模板](#part-2)一次交齐本轮资产、采用版本、参考职责、状态及待补项。若用户只要后续成品，清单供内部使用，必要的素材准备项随成品给出。

<a id="image-registration"></a>
## 真实图片登记（所需资产表之后）

交所需资产表后，用户指定哪些聊天生成图或回传图要登记、对应剧本哪个对象，就登记这些图，不把所有聊天图自动采用。固定顺序：用户指认 → 核稳定对象/状态 → 核实际图片及保存能力 → 建真实图片ID → 记录职责与可用性 → 读回登记。匹配清楚直接登记，只有原文、图像与指认确实矛盾或对应不清才询问，不能反复让用户确认已经说清的名称。

按[记录契约](../项目记录契约.md)优先调用 `工具/项目管理.cjs register-image` 将 images 写入项目唯一权威记录（自动算文件 SHA-256 并刷新总览图片登记视图）。至少保存：图片ID、对象ID、用户命名、外观/布局/伤势等视觉 `state`（视觉职责图不得留空 `{}` 以免漏检）、文件及版本、上传/生成来源定位、用户指认依据、`viewed`（无读图能力须填 `unviewedAck`）、`roles`、`status`。正常与受伤是同一人物的状态图；图片版本不是新人物身份。

| 图片ID/对象 | 名称与状态 | 实际文件/来源定位 | 职责/适用范围 | 查看/可用/采用情况 |
|---|---|---|---|---|
| 按本次真实登记填写 | 用户指认及有依据的可见状态 | 已保存相对路径或真实会话来源 | 实际维度和冲突边界 | 如实区分 |

上表为展示模板，不另存第二套手工事实。可导出时把真实图片按对象/状态归类保存并核文件；没有导出能力标session-only/未落盘，说明跨对话无法恢复并请提供可保存文件，不编造路径或素材ID。未查看的图按用户说明登记并注明，不假称视觉确认。没有生成成功的图不能记为available。

同一上传批次的图1只作来源定位，不当永久图ID；第四步块内直接用清晰的图片名称声明职责，块外对照表列明登记ID与路径由创作者自行上传绑定。人物/场景状态范围来自源文事件，不从图片猜生死或伤势生效时间。图片命名匹配但视觉明显矛盾时先核，不带错图进入生成。

## 只核点名素材

定位用户点名的对象和现有资产号，按[版本与参考职责](#part-10)核文件、版本、可见依据和适用范围。只回填该对象的采用版本、职责、状态和会影响成品的缺项。更换素材后如外观、布局或状态改变，检查对应事件、镜头和提示词。

## 交接

逐段绑定使用同一条可追溯映射：资产号→稳定对象名→实际文件/版本→采用职责→适用源镜→块内清晰图片名称（块外对照表供创作者自绑）。已提供、已查看、已采用、已绑定分开记，02不硬绑特定平台槽位语法，04块内用清晰图片名称声明职责且不覆盖对象身份。场景布局依据交03，03产出动态站位后交04[信息去向核对](../04-提示词/流程.md#information-mapping)。没有实际绑定就不输出空素材栏，必要准备项写块外。

03 按稳定资产号取得对象、外观或空间固定项，以及事件中的变化，并按[空间基准与调度](../空间基准与调度.md#space-baseline)建立人物初始站位和动态状态。本步管理场景固定布局，不将人物逐镜站位当作永久资产设定；布局变化须注明版本与受影响范围。04 按实际生成单元核对所需图片名称、版本、职责及音色参考。素材仅发生替换时，先核采用版和参考职责；若固定外观、布局或状态发生实质变化，再检查受影响的镜头。

<a id="part-10-版本与参考职责"></a>
<a id="part-10"></a>
## 版本与参考职责

1. 对照原稿、已确认设定和可用素材。素材提供、可观察和采用是不同状态；同一对象可以有多个候选，采用哪一版、用于哪些镜头要明确。
2. 给每份采用素材说明具体职责，例如人物图参考脸部与服装，场景图参考布局与主光，动作视频参考动作，音频只参考音色。只写实际可见或用户明确指定的范围。职责冲突时定位到版本、对象及受影响的镜头。
3. 把需要用户准备、补交或确认的内容单列，说明它影响哪一事件、镜头或生成输入。已有素材信息可沿用；无法查看时按用户已提供的说明登记。
4. 本步用稳定资产号关联对象与文件。每次生成块内使用的清晰图片名称与块外上传对照由第四步核对，由创作者在目标平台自行绑定。每份素材的采用范围记录到相应事件、镜头或生成单元。素材替换时优先更新版本和职责，再回查受影响的画面条件。

在资产清单的参考职责记录中，图上已有且本次采用的内容写「依据」，修改已有内容写「调整」，图上没有且本次明确新增的内容写「补充」。场景素材须分清锁定布局、仅参考外观材质或仅参考气氛；未提供的背面、画外区域与尺寸不从单张图擅自确定。人物参考不自动锁定其在场景中的站位。

<a id="part-11-资产识别与状态记录"></a>
<a id="part-11"></a>
## 资产识别与状态记录

按事件从画面、发声和执行需要三处找资产。先列角色、场景与关键道具，再登记实际有用的声音、动作或布局参考（首尾帧参考**仅在用户主动提供素材或明确要求首尾帧模式时**才登记，常规流程绝不默认要求准备首尾帧）。只存在于画外的声音也可成为独立资产；无需独立参考的普通陈设可归入场景。

| 对象 | 记录与下游有关的字段 |
|---|---|
| 角色 | 稳定名称与编号、已确认身份、固定外观或服装、固定音色和阶段状态 |
| 场景 | 布局版本、固定地标之间的相对关系、可用区域、通道及障碍、必要支撑与高低差、基础光源和可见边界；区分已采用固定项与尚可设计项，不只罗列物件名 |
| 道具 | 外形、尺度、功能、完损，以及使用、接触和持有人变化 |
| 声音或辅助参考 | 来源、适用事件或镜头、约束的维度及使用范围；角色声音资产默认采用[声纹锁图](#voiceprint-lock)或已提供的参考音色 |

同一对象跨事件使用同一编号，状态变化另记。例如道具从“角色甲右手握持”到“甲与乙共同接触”再到“乙持有”，归在同一个资产。物件归属、当前持有人与接触阶段分别写清。草稿可以标待定，涉及原稿结果或关键辨识特征的新增设计应先核依据。

<a id="voiceprint-lock"></a>
## 声音资产（声纹锁图）与人物特征对齐

资产清单中列出的角色声音资产默认为**可视化声纹锁图**（纯白底极简黑白声波纹 + 下方英文声纹特征词），并按以下三档优先级绑定到每个发声角色：

1. **参考音色优先**：用户提供了参考音色/参考音频时，**以参考音色为主**，直接登记该参考音色名称与来源，不必另做声纹锁图。
2. **未提供参考音色 → 统一绑定声纹锁图**：为每个有发声需求的角色建立独立声音资产（如 `V01｜林岚-声纹锁图`），在角色行后缀标明对应绑定，并在声音资产区附带标准化出图提示词（长剧项目模式登记进 `项目.json` 时，直接关联该角色 `objectId` 或填 `forObjectId`，`roles` 填 `["voice"]`）。
3. **不做任何资产图（纯文生视频）**：自动退化为把同一组声纹特征词作为纯文字后缀，挂在 04 块首【角色与场景固定外观（纯文字锁）】的人物后。

### 5 词推导与防“声人不符”红线

生成每条声纹锁时，必须严格从角色设定反推 **4–6 个英文短词入图**（同时在表内附中文核对说明）：`① 性别与年龄感（如 Young male / Mid-20s female）＋ ② 音区厚度/温度（如 warm / cool low-mid / deep resonant）＋ ③ 音质纹理（如 clear / slightly husky / gravelly）＋ ④ 吐字节奏感（如 agile / crisp / unhurried）＋ ⑤ 性格语感底色（如 dryly humorous / calm restrained；口音或永久嗓伤仅在原稿明确给定时才写）`。

- **人设四项必核**：逐项核对角色性别、年龄段、体型气场与身份经历，严禁出现“硬汉配少年音”“清冷御姐配甜腻萝莉音”等声人不符。
- **底色与临时表演分离**：哭腔、怒吼、耳语、重伤喘息属于当镜说法或阶段状态，**严禁写死进永久声纹锁**。
- **同场同性区隔**：同场出现 2 名及以上同性别发声角色时，至少在音区、音质或节奏拉开 1–2 个维度，防模型混音；无台词背景群演不强建声音资产。

**声纹锁图一键生图提示词模板**（仅对未提供参考音色、需生成声纹锁图的角色输出）：
`纯白背景，居中一条极简细密的黑白水平音频声波纹，声波正下方居中排版优雅的黑色衬线斜体英文文字："[该角色英文声纹词]"，画面极度干净，无边框，无图标，无多余杂物，横版信息卡构图。`
