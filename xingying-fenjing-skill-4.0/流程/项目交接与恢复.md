# 项目交接与恢复

本文件是4.0项目管理的唯一方法入口。剧情状态交[连续性方法](剧情连续性与状态管理.md)，强制设置交[选项确认](制作设置与强制确认.md)，运行中途插话与局部改稿交[中途建议与局部修订专册](中途建议与局部修订专册.md)。不另建平行采用账。

## 双模式分流：轻量单场 vs 长剧项目

| 模式 | 适用场景 | 执行方式 |
|---|---|---|
| **轻量单场模式** | 用户只发单段/单场短剧情、未指定项目目录、无跨集/跨对话续做或真实参考图归档需求 | 不强建8目录与 `项目.json`；每轮通过回复顶部一行 `【星应进度锚点】`（见[防失忆锚点条](中途建议与局部修订专册.md#state-anchor-bar)，置于复制块外）在当前会话内持续锁定阶段进度、制作基准、空间快照与挂起待办，防止多轮对话失忆。用户随时要求归档或续写下一集时，立即 `init` 升级为项目模式并保全前稿。 |
| **长剧项目模式** | 用户指定项目目录、目录已有 `项目.json`、明确做多集/分批长剧、要求跨对话恢复或登记真实图片 | 全部01—04任务必须走[开工关卡](#project-gates)，使用 `工具/项目管理.cjs` 的读写 CLI 维护 `项目.json` 唯一权威记录，不因“只要最终成品”或“一次交齐”跳过。 |

## 项目目录与权威记录

Skill安装目录不是用户影片项目目录。先定位用户指定项目；没有明确位置且无法可靠确定时只问保存位置，不把安装包当项目写。已有项目先读取入口和原有记录，建立路径映射，不擅自迁移或覆盖。

新项目在确认的目录用本包 `工具/项目管理.cjs init <项目目录> <项目ID>` 初始化。只创建不存在的文件，遇已有权威记录停止覆盖。没有脚本能力时按[记录契约](项目记录契约.md)写等价数据并人工核查，不能声称运行过脚本。

```text
项目目录/
├─ 项目入口.md                       导航与恢复方式，不手改生成内容
├─ 00-项目管理/
│  ├─ 项目.json                      唯一机器记录，所有摘要由它派生
│  └─ 项目总览.md                    进度、采用稿、状态/图片索引与阻塞，只读派生视图
├─ 01-剧本/原始输入/                 收到的原稿保全；分集采用稿按需另存
├─ 02-连续性/                       按需保存原文核对报告，状态事件权威值在项目.json
├─ 03-资产/人物/                     按对象/状态ID归类；场景、道具、辅助参考同理
├─ 04-分镜/                         按集/场归档，含内部镜头记录
├─ 05-分段提示词/                   按集/场/段归档
├─ 06-生成与验收/                   实际素材及实测验收，不冒充已生成
└─ 99-垃圾箱/                       按原类别/对象/集场归档
```

不要为未来集数创建成百上千空文件。项目入口必须直接指向当前剧本、状态变化和图片登记索引。旧项目的 `采用版.md`、内部十四项等保留文件，只把实际采用关系映射进记录；同一事实迁入权威记录后，旧表标历史或派生，不两边独立更新。原始剧本永不被状态表替代。

项目.json 管身份、路径与哈希、采用关系、工作单元、状态事件、图片登记、设置、依赖、冲突和检查证据。完整剧本、分镜和提示词单独存文件；不把全文塞进JSON。字段见[项目记录契约](项目记录契约.md)。项目总览由 `render` 生成，禁止手工维护第二套进度/状态数字。

<a id="project-gates"></a>
## 开工关卡与统一链路

```text
G0 恢复项目/集场段/进度/采用版/阻塞
→ G1 读取当前采用原文、版本和故事时点，解析相关对象有效状态
→ G2 核适用制作及分段设置的真实确认来源
→ 01 剧本与状态事件 → 02 所需资产/真实图片登记 → 03 排镜/内部十四项（唯一视频母稿）
→ 04 统一视频提示词（按段或整场单块）/ 分镜图提示词
→ G3 每段有效状态与必需参考/实际绑定双向核对
→ G4 完整正文、时间、摄影、空间、承接和原词验收
→ G5 保存读回/依赖核对/进度更新 → 交付简报
```

每次阶段进入、每段装配前及上游变更后都核相应关卡。仅整理原文或单项登记只做适用项；不问当前完全无关的未来设置。已有有效设计直接复用，不重排全部镜头。首次导入先保全用户原稿，01建立最小身份/状态基准再核G1，不因尚无状态表无限回退。

| 关卡 | 必须核到的证据 | 失败回退 |
|---|---|---|
| G0 | 项目ID、当前范围、唯一权威记录、工作位置、采用文件、开放冲突 | 读记录自行恢复；真正多义才问，不凭当前编辑器文件猜项目 |
| G1 | 采用剧本原文定位、哈希/版本、故事时点、相关人物生死/伤势及场景道具状态 | 下游乱写按原稿修；源资料真冲突才列证据确认，不编假死或治愈 |
| G2 | 设置值、明确回答或专项授权来源、作用范围 | 实际弹未知项的卡，等待时不交依赖该项的定案稿 |
| G3 | 本段逐镜状态观察点、参考需求、登记图、版本/职责/清晰图片名称/作用镜头阶段 | 缺图回02（缺状态图或不做图可按04 G3弹卡授权走纯文字锁或正常图+文字补状态，未经授权严禁凑错图），事实回01，普通设计回03；仅阻塞受影响范围 |
| G4 | 实际成稿而非“已检查”，源镜展开、时间成立、承接和信息保真 | 局部回责任步骤修，锁定冲突确认 |
| G5 | 产物落盘读回、版本依赖一致、管理记录和下一步更新、检查证据可追溯 | 保持未完成/保存失败，不能宣布可恢复或已完成 |

制作设置必须保存确认或授权来源和范围（支持 `EP001` 层级前缀自动覆盖 `EP001/SC001`）；概括性授权不能替代具体设置的专项确认。每关检查使用**分阶段指纹**（`G0—G2` 核前置原料与设置、`G3` 核观察点与图片绑定、`G4—G5` 核成稿落盘），从而按真实顺序逐关盖章，且后续标“已采用”或导入新集数不会误冲毁前集已通过关卡。任何没有来源的“通过”都不算关卡完成。脚本结构检查不替代G1语义核对、实际弹卡和G4正文审阅。

## 工作状态、采用与进度

按集—场—段—阶段建工作单元，不用“已完成第几集”掩盖集内缺口。工作状态（未开始/进行中/待确认/阻塞/已交付）、采用状态（草稿/候选/已采用/已替代）、检查状态（未检查/通过/失败/待复核）分开。某段提示词已交付不代表视频已生成，更不代表已验收。

用户未确认采用时自动保存草稿，不自动将其登记为采用稿。用户明确多步直出，可在同一任务内引用标明的工作版本继续，最终保持候选；不可因此强迫每个内部步骤都等确认，也不可冒充用户采用。工作版依赖写明，获采用后才更新采用路由。

计划总长、提示词覆盖时长、实际采用成片时长分别记录。真实成片需有可核素材与保留区间；叠化重叠去重，不把估算当实测。总览统计从工作单元派生。

## 保存、读回与中断

每个完整场/段批次以及设置回答、图片登记、重大剧情变更后保存检查点。先保存产物与证据，读回核对，再更新项目.json中的文档哈希、输入依赖、单元与采用路由（仅获采用时），运行检查，生成总览并读回关键引用。

项目.json 所有写入优先调用 `工具/项目管理.cjs` 的写入子命令（底层由 `工具/项目写入.cjs` 执行临时文件原子替换、递增 `revision`、`--expected-revision` 乐观锁防覆盖，并自动校验与 `render` 刷新总览），不要手工拼接 SHA-256 或指纹。多文件非事务时先 `begin-batch`，全部产物落盘并通过 G4/G5 后用 `mark-unit --commit-batch <批次ID>` 原子交付提交；任何一步失败保留 `pending` 以便恢复对账。禁止在检查失败时修改“通过”字段掩盖问题。

常用执行命令（完整参数见[项目记录契约](项目记录契约.md)）：

```text
node "<Skill目录>/工具/项目管理.cjs" check|status|render "<项目目录>"
node "<Skill目录>/工具/项目管理.cjs" state "<项目目录>" "<对象ID>" "<timeline>" "<point>"
node "<Skill目录>/工具/项目管理.cjs" add-doc|adopt|add-object|add-event|register-image|set-setting "<项目目录>" ...
node "<Skill目录>/工具/项目管理.cjs" upsert-unit|record-check|mark-unit|trash "<项目目录>" ...
```

check/status/state 只读不改权威记录；写入命令先在内存中预校验不变量，失败不落盘且退出码非零；`trash` 会先拦截仍被采用路由或活跃单元引用的文件。工具不自动创作剧本或判定原文含义。

<a id="内部镜头记录"></a>
## 内部镜头记录

完整十四项随分镜版本单独存（作为 04 视频提示词的唯一转写母稿），项目记录引用其文档ID、源镜和版本。保存观看任务、可见证据、导演采用依据、场级空间、切入切出、动作覆盖/插入/接回、时长依据、变速与声画职责、分段映射和有效尾态。沿用原有方法，不增加第十五列，不强迫展示内部记录。

新增引用：本镜关联源事件/状态事件ID、故事时点、对象有效入态/变化/出态、所需参考职责及每段实际图、清晰图片名称与职责范围。人物出画不丢状态，段内变化按接点拆观察点；不能用一个段首状态覆盖整段。

恢复时保留既定拍法和参数、持续动作阶段、镜头顺序及整数段长等规则。理由未记录不倒推作者心理，不为补理由重排镜头；必要事实缺失则回源。

## 跨对话恢复

固定顺序：项目入口/项目.json → 开放冲突与当前工作位置 → 本范围采用剧本原文和设置 → 涉及对象的状态事件与生效时点 → 实际图片可用性 → 对应分镜/内部记录/视频提示词及前段有效尾态。先运行check或人工同等核查。

先给简短简报：项目、集场段、阶段、采用版本、相关素材是否齐、阻塞/待复核、下一步。无歧义就继续，不让用户重复已经在文件里的答案。读取失败或哈希变化先核原稿，不凭记忆补。

长项目分层读取：入口查索引，当前集读完整适用原文，人物查有关历史，关键事实沿引用回源。每集开工和重大变更重核入出态，每段核有关对象；同批已读且版本未变可复用，不每段吞整剧，也不能只看上一段。已收剧本范围和缺集明记，未知后续不编造。

## 变更传播与垃圾箱

上游采用剧本、状态、图像职责改变后，先运行 `node "<Skill目录>/工具/项目管理.cjs" affected "<项目目录>" "<变更ID>"` 查文档/对象/事件/镜头/单元依赖，列直接与间接候选范围，再按实际故事时点和职责核定受影响范围，标待复核。旧检查的输入指纹失效；未复核结果不得作为已验证输入继续交付。用户选择修订范围后产修订草稿，保留旧采用版，获采用再换路由。仅换同状态图片也需检查绑定、图片名称与块外上传对照。

垃圾箱按图片/原对象、弃用稿/原集场、其他/原类别归档，登记原路径、归档路径、原因、替代物、引用处理和恢复办法。先查全项目采用和历史引用；仅本段不用不代表全项目无用。未获整理授权不擅移，原始剧本和有效证据不删，默认不永久删除。默认选图与恢复不读垃圾箱；历史回溯可显式读，但不能因此选为现行素材。
